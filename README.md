# claude-harness

Mark Dhas's user-level harness for Claude Code: global working rules, skills, commands and a subagent.
Everything installs into `~/.claude/`, so it applies in every repository on the machine.

> **Status: work in progress.** analyze-codebase has been run against real repositories; red-team,
> architecture-review, blast-radius and commit are written but still being tested. Expect changes.
> See `ROADMAP.md`.

## Install

```bash
git clone <this repo> ~/workspace/skills
cd ~/workspace/skills
./install.sh --link     # symlinks: `git pull` keeps every machine in sync
# or
./install.sh            # plain copies
```

Existing files in `~/.claude` are backed up to `~/.claude/backup-<timestamp>/` before anything is replaced.
Start a new Claude Code session afterwards.

## What's in it

| Path (under `home/`) | Kind | Purpose |
|---|---|---|
| `CLAUDE.md` | Global rules | How to work in any repo: explore, plan, test first, verify, boundaries, reporting |
| `shared/danger-levels.md` | Shared reference | None / Trivial / Low / Medium / High / Critical scale for changes, with escalation rules |
| `skills/analyze-codebase/` | Skill | Onboard onto a repo in three modes: `--quick` (read-only reconnaissance in chat, about two minutes), standard (adds test baseline, metrics and a drafted CLAUDE.md) and `--deep` (adds a size-budgeted codebase map). Profiles: node, python, php, go |
| `skills/red-team/` | Skill | Attack a codebase, path or diff; every finding proven by a failing test |
| `skills/red-team/` | Skill | Attack code in three modes: `--quick` (default; last 10 commits plus uncommitted work), `--diff` (pre-commit) and `--deep` (whole codebase, parallel attackers by area). Every finding proven by a failing test |
| `skills/architecture-review/` | Skill | Evidence-based review: dependency graph, complexity, git hotspots, change coupling, coverage, layered guidelines |
| `skills/blast-radius/` | Skill | Impact map for a change: dependents, dynamic links, history coupling, surfaces, contracts, tests, danger rating |
| `skills/commit/` | Skill | Commit with a danger rating, level-based gates and `Danger:` trailers; never pushes |
| `commands/plan.md` | Command | `/plan <task>`: numbered plan, tests first, edge cases, then wait |
| `commands/verify.md` | Command | `/verify`: run tests, review the diff, list fixes before merging |

## Usage

```
/analyze-codebase [ecosystem|framework] [version] [--quick | --deep] [--update] [--map-only]
                  [--scope <dir>] [--skip-tests] [--skip-coverage]
                  [--output-file-path <path>] [--trust]
/red-team [--quick | --diff | --deep] [--commits <n>] [path]
/architecture-review [path]
/blast-radius <file | file:line | file:symbol | --diff> [intended change]
/commit [message hint]
/plan <task>
/verify
```

Skills also trigger from natural language ("analyze this codebase", "what's the blast radius of changing X").

## Design notes

- Global rules travel with you; each repo gets its own project CLAUDE.md (generated by /analyze-codebase).
- Procedures are stable; ecosystem knowledge lives in swappable profile and guideline files.
- Read-only by default. Anything that writes asks first, unless explicitly told otherwise.
- Danger ratings are defined once (`shared/danger-levels.md`) and used by both /commit and /blast-radius.

See `ROADMAP.md` for planned work.
